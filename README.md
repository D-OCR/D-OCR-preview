# D-OCR Preview Docker

CPU and NVIDIA GPU Docker setups for D-OCR document recognition, layout detection and table extraction. Required weights and the compiled runtime download automatically from [Hugging Face](https://huggingface.co/D-OCR/D-OCR-preview) during the build.

## Quick start

Requires Linux x86-64, Docker with BuildKit and Docker Compose v2. GPU use also requires a CUDA/BF16-capable NVIDIA GPU, a compatible driver and NVIDIA Container Toolkit. Allow plenty of free space on Docker's storage disk: model downloads alone are about 2.4 GiB, and dependencies, image layers and build caches require considerably more. CPU inference can be slow.

```bash
git clone https://github.com/D-OCR/D-OCR-preview.git
cd D-OCR-preview

# Generate your own local API key; keep .env private.
umask 077
printf 'OCR_API_KEYS=%s\n' "$(openssl rand -hex 32)" > .env
```

Choose **one** setup:

```bash
# CPU
docker compose -f compose.cpu.yml up -d --build --wait --wait-timeout 600
```

```bash
# NVIDIA GPU
docker compose -f compose.gpu.yml up -d --build --wait --wait-timeout 600
```

Open **http://localhost:8000/docs**, click **Authorize**, and paste the key value from `.env`. Submit an image or PDF through `POST /v1/ocr` and wait for the response. The API provides recognized text, detected regions, table data and HTML layout views. See the [usage guide](https://huggingface.co/D-OCR/D-OCR-preview/blob/main/USER_GUIDE.md) for asynchronous jobs and saving outputs, and the [detection examples](https://huggingface.co/D-OCR/D-OCR-preview).

The API key is generated by you to protect your local service. No purchased API key or Hugging Face token is required for these public downloads. This package runs the backend and its browser API testing interface; the original web frontend is not included.

## Run OCR with the Python script

[`ocr_test_script.py`](ocr_test_script.py) submits an image or PDF to the running service and saves the response as readable UTF-8 JSON, preserving Bengali characters. Start the CPU or GPU container using the commands above before running it.

From the repository directory, install the script's dependencies in a virtual environment:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install requests python-dotenv
```

Keep your existing API key in the `.env` beside the script. The script loads it automatically; you do not need to source `.env` in your terminal. If `OCR_API_KEYS` contains multiple comma-separated keys, the script uses the first. An already exported `OCR_API_KEYS` takes precedence over `.env`, so it must match a key accepted by the running container.

Run it with the input file path and an optional output file path:

```bash
python ocr_test_script.py /path/to/document.jpeg

# Choose an output filename; quote paths containing spaces.
python ocr_test_script.py "/path/to/document.pdf" "my-ocr-result.json"
```

- The default output is `ocr-result.json` in your current directory. An existing output file is overwritten.
- Each invocation performs a **new OCR request** using `POST http://localhost:8000/v1/ocr`. It waits for the result instead of returning a job ID or polling progress.
- The request timeout is 1,800 seconds (30 minutes). CPU processing can take several minutes; the script prints its HTTP status only after receiving the response.
- On success, it prints `HTTP 200` and `Saved response to ...`. The JSON contains recognized `text`, per-page `pages`, document structure, and HTML views. This synchronous response does not have the asynchronous job's outer `status`/`result` wrapper.
- If you changed the service port, update `API_URL` near the top of the script to match. For `Missing or invalid API key`, check that the script and container use the same key. For connection errors, check that the container is running and the URL is correct.

## Downloads and storage

- The first build needs internet access for models and dependencies. Model assets are pinned to Hugging Face revision `4b557b4626bdfb39db3d7a0aed120a853092c0db` and checked against its size/SHA-256 manifest.
- Downloaded assets are cached during builds and included in the image. Inference and container restarts do not download weights again.
- Uploads and results persist in the `docr-data` Docker volume. The API binds to localhost by default.
- Stop CPU with `docker compose -f compose.cpu.yml down`; use `compose.gpu.yml` for GPU. This preserves stored data. Use only one setup at a time.
- `Dockerfile.cpu` and `Dockerfile.gpu` are standalone; the generic `Dockerfile` defaults to GPU and also supports `--target cpu`.

## Preview status

Automatic asset downloads, checksums and CPU dependency installation have been checked. A local CPU Docker run completed OCR on the Bengali document shown in the video demo. This is a single-document check, not a general accuracy or performance benchmark. GPU Docker execution remains unvalidated. Earlier compiled-runtime inference checks and current limitations are documented in [VALIDATION.md](https://huggingface.co/D-OCR/D-OCR-preview/blob/main/VALIDATION.md). Review OCR output; detection and table reconstruction remain experimental.
